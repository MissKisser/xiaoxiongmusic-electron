# SPlayer 代码同步规范

本文档规范了从 SPlayer 同步代码到小熊音乐项目的操作流程、注意事项和限制条件。

## 一、项目概述

### 1.1 项目关系

- **上游项目**: SPlayer（开源音乐播放器）
- **本项目**: 小熊音乐（基于 SPlayer 的二次开发版本）
- **同步目标**: 保持与上游核心功能同步，同时保留二次开发内容

### 1.2 二次开发内容清单

以下内容为本项目独有，同步时必须保留：

| 模块 | 文件路径 | 功能说明 |
|------|----------|----------|
| 均衡器 | `src/components/Modal/Setting/Equalizer.vue` | 音频均衡器调节 |
| 歌曲百科 | `src/views/Song/SongWiki.vue` | 歌曲信息百科展示 |
| 授权系统 | `server/routes/auth.ts`, `server/routes/admin.ts` | 用户授权验证和管理后台 |
| Admin WebUI | `src/views/Admin/*.vue` | 管理后台界面（Dashboard、Codes、Versions、Logs、Login、Layout） |
| 流媒体歌词 | `src/utils/lyric/*.ts` | QQLyricParser 等歌词解析工具 |
| 解锁服务 | `electron/server/unblock/*.ts` | 歌曲解锁服务（kuwo、kuwo_desktop、gequbao、bodian、match） |
| 原生工具 | `native/tools/` | 原生模块工具（构建时可能需要跳过） |

### 1.3 Admin WebUI 技术栈

- Vue 3 + TypeScript + Naive UI
- 主题切换: 白色主题（默认）+ 深色模式（可切换）
- 布局结构: `Layout.vue` → `Dashboard.vue` / `Codes.vue` / `Versions.vue` / `Logs.vue` / `Login.vue`

## 二、代码同步对齐流程

### 2.1 分析上游更新

**第一步：查看 SPlayer GitHub 仓库的最新提交**

```bash
# 访问 SPlayer GitHub 仓库
https://github.com/imsyy/SPlayer

# 查看最新 commits
https://github.com/imsyy/SPlayer/commits/main
```

**重点关注**：
- 提交时间和提交数量
- 提交描述中提到的功能变更、bug修复、重构等
- 涉及的文件路径

### 2.2 确定同步范围

**第二步：逐条分析提交内容，判断是否需要同步**

| 提交类型 | 是否同步 | 说明 |
|----------|----------|------|
| 核心功能更新（播放器、解码、API） | ✅ 需要同步 | 核心功能改进 |
| UI/样式更新（主界面、组件样式） | ⚠️ 评估后同步 | 可能与二次开发 UI 冲突 |
| Bug 修复 | ✅ 需要同步 | 修复问题 |
| 依赖更新 | ⚠️ 评估后同步 | 可能影响原生模块 |
| 新增功能 | ⚠️ 评估后同步 | 判断是否与二次开发冲突 |
| 配置文件更新 | ❌ 不同步 | 本项目有独立配置 |
| 文档更新 | ❌ 不同步 | 不影响代码 |

**第三步：进入提交详情查看具体变更**

```
# 点击具体 commit，查看 diff
https://github.com/imsyy/SPlayer/commit/<commit-hash>

# 关键信息：
1. Files changed - 变更文件列表
2. 具体代码 diff - 新增/删除/修改的代码行
```

### 2.3 对比本项目代码

**第四步：本地对比，确定差异**

```bash
# 1. 获取上游最新代码
git fetch splayer

# 2. 查看上游变更文件
git diff HEAD splayer/main --name-only

# 3. 对比具体文件差异
git diff HEAD splayer/main -- <文件路径>

# 4. 查看上游提交日志
git log splayer/main --oneline -20
```

**第五步：逐文件分析差异**

对于每个变更文件：

```bash
# 使用 diff 工具详细对比
git diff HEAD splayer/main -- src/core/player/PlayerController.ts
```

分析要点：
1. **新增代码** - 是否需要引入本项目
2. **删除代码** - 本项目是否有对应代码，是否需要同步删除
3. **修改代码** - 本项目是否有二次开发修改，是否冲突
4. **冲突判断** - 变更是否影响二次开发内容

### 2.4 冲突预判清单

**第六步：建立同步清单，标注冲突情况**

```
| 文件路径 | 变更类型 | 冲突风险 | 处理方案 |
|----------|----------|----------|----------|
| src/core/player/*.ts | 修改 | 低 | 直接同步 |
| src/api/*.ts | 新增 | 低 | 直接同步 |
| src/views/Home.vue | 修改 | 中 | 合并，保留本项目 UI |
| src/components/Player/*.vue | 修改 | 高 | 保留本项目修改 |
| electron/main/*.ts | 修改 | 中 | 检查二次开发内容 |
| server/*.ts | 新增 | 低 | 直接同步（非授权系统） |
```

### 2.5 同步前检查

**第七步：最终确认**

```bash
# 1. 确认二次开发文件状态
git status src/views/Admin/
git status src/components/Modal/Setting/Equalizer.vue
git status server/routes/auth.ts server/routes/admin.ts

> **注意(2026-07-28 更新)**:`server/` 已抽取为独立仓库 [xiaoxiongmusic-server](https://github.com/MissKisser/xiaoxiongmusic-server),作为 git submodule 引用。上列 server 相关条目(`server/routes/*.ts`、`server/db.ts` 等)**已不在本仓库**,后续 server 改动请在 server 仓库进行。SPlayer 上游同步不再涉及 server/。

# 2. 确认无未提交更改（或先暂存）
git stash  # 如果有未完成工作

# 3. 记录当前版本
git log --oneline -1
```

### 2.6 执行同步

**第八步：执行合并**

```bash
# 合并上游代码
git merge splayer/main --no-edit

# 如果有冲突，按预判清单处理
git status  # 查看冲突文件
```

### 2.7 冲突解决原则

| 冲突类型 | 解决方案 |
|----------|----------|
| 核心文件冲突（player、api、stores） | 合并上游改进，保留本项目扩展 |
| 配置文件冲突（CLAUDE.md、.env） | 保留本项目配置 |
| 二次开发文件冲突 | 坚决保留本项目版本 |
| 样式冲突 | 合并两者，优先本项目样式 |

### 2.8 Git 提交规范

#### 提交信息格式

使用中文提交信息，格式简洁清晰：

```
<类型>: <简短描述>

[可选的详细说明]
```

**类型分类**:
- `同步` - 从上游 SPlayer 同步代码
- `修复` - 修复 bug
- `优化` - 性能或体验优化
- `新增` - 新增功能
- `重构` - 代码重构
- `更新` - 更新依赖或配置

#### 同步提交示例

```bash
# 从上游同步后提交
git add .
git commit -m "同步: 从 SPlayer 同步最新代码

- 更新播放器核心逻辑
- 同步 API 接口变更
- 保留二次开发内容（均衡器、SongWiki、授权系统）"
```

#### 提交限制

**必须遵守**:

1. **不添加 Co-Authored-By**: 提交代码时只使用实际的用户名和邮箱，不添加联合作者标记
2. **不包含 AI 生成痕迹**: commit message 中禁止出现 "Generated by Claude"、"AI-generated" 等字样
3. **使用中文**: 提交信息使用中文描述

**禁止的提交格式**:
```bash
# ❌ 错误示例 - 包含 Co-Authored-By
git commit -m "同步上游代码

Co-Authored-By: Claude <noreply@anthropic.com>"

# ❌ 错误示例 - 包含 AI 痕迹
git commit -m "AI生成的代码修复"
```

**正确的提交格式**:
```bash
# ✅ 正确示例
git commit -m "同步: 从 SPlayer 同步播放器核心代码"
```

#### 合并上游后的提交流程

```bash
# 1. 查看合并状态
git status

# 2. 检查冲突文件
git diff --name-only --diff-filter=U

# 3. 解决冲突后暂存
git add <解决后的文件>

# 4. 完成合并提交（Git 会自动生成合并提交信息，检查并修改）
git commit

# 5. 如果需要修改合并提交信息
git commit --amend -m "同步: 合并 SPlayer 上游更新 v3.x.x"
```

## 三、Admin WebUI 修改规范

### 3.1 布局结构

```
Layout.vue（布局容器）
├── admin-sider（侧边栏 220px）
├── admin-header（顶部栏 60px）
└── admin-content（内容区域）
    └── n-scrollbar（Naive UI 滚动容器）
        └── n-scrollbar-content
            └── content-center（居中容器 max-width: 1200px）
                └── [子页面组件]
```

### 3.2 内容居中关键点

**重要**: Naive UI 的 `n-layout-content` 会自动包裹 `n-scrollbar`，导致 flex 居中失效。

解决方案（Layout.vue）:
```scss
.admin-content {
  // Naive UI scrollbar 居中
  :deep(.n-scrollbar),
  :deep(.n-scrollbar-container),
  :deep(.n-scrollbar-content) {
    display: flex;
    justify-content: center;
  }

  .content-center {
    width: 100%;
    max-width: 1200px;
  }
}
```

### 3.3 主题切换机制

- 使用 `provide/inject` 传递主题状态
- `Layout.vue`: `provide('adminTheme', isDark)`
- 子组件: `inject('adminTheme', ref(false))`
- CSS 类切换: `.dark-mode`

### 3.4 DataTable 排序功能

```typescript
// 必须添加 sorter 属性才能启用表头排序
const columns = [
  {
    title: '授权码',
    key: 'code',
    sorter: (a, b) => a.code.localeCompare(b.code),  // 排序函数
    render: (row) => h('code', {}, row.code),
  },
  {
    title: '活跃时间',
    key: 'lastActiveAt',
    defaultSortOrder: 'descend' as const,  // TypeScript 类型必须加 as const
    sorter: (a, b) => new Date(a.lastActiveAt).getTime() - new Date(b.lastActiveAt).getTime(),
  },
];
```

### 3.5 TypeScript 类型规范

```typescript
// DataTableColumns 类型必须导入
import { type DataTableColumns } from 'naive-ui';

// selection 列必须加 as const
const columns: DataTableColumns<AuthCode> = [
  { type: 'selection' as const },  // 必须加 as const
  ...
];
```

## 四、部署流程

### 4.1 本地构建

```bash
# Web 端构建（跳过原生模块）
SKIP_NATIVE_BUILD=true pnpm build:web

# 或使用 npm
export SKIP_NATIVE_BUILD=true && npm run build:web
```

### 4.2 常见构建问题

| 问题 | 解决方案 |
|------|----------|
| 原生模块构建失败 | 设置 `SKIP_NATIVE_BUILD=true` |
| TypeScript 类型错误 | 检查 `as const`、类型导入 |
| 端口占用（25884） | `lsof -i :25884` 然后 `kill -9 PID` |

## 五、限制条件

### 5.1 禁止操作

1. **不要删除二次开发文件**: 均衡器、SongWiki、Admin WebUI 等
2. **不要覆盖授权系统**: auth.ts、admin.ts 必须保留
3. **不要修改数据库密码**: 使用现有配置
4. **不要全量构建**: 优先上传修改文件

### 5.2 必须保留

1. 二次开发内容（见 1.2 清单）
2. 项目配置（CLAUDE.md、.env、ecosystem.config.cjs）
3. Admin WebUI 的主题和布局设置

### 5.3 注意事项

1. 原生模块可能无法构建，跳过即可
2. Naive UI 的 scrollbar 会影响 flex 居中，需要 `:deep()` 穿透
3. TypeScript 类型必须严格，`as const` 不能省略
4. PM2 进程可能因端口占用重启失败，需先清理

## 六、快速检查清单

同步/修改完成后，检查以下项目：

- [ ] 二次开发文件是否保留
- [ ] Admin WebUI 布局是否居中（侧边栏左侧，内容居中）
- [ ] 表头排序是否正常
- [ ] 主题切换是否正常（白色/深色）
- [ ] 构建是否成功
